02本轮落地的优化（含实测数据）

已落地京东取数改为「响应截获」—— 并推翻了一条错误结论

错误结论（已存在多日）：MEMORY 与旧调研报告都写着「京东桌面搜索页是 服务端渲染 HTML，没有 JSON 接口可截获」，并据此把京东排除在「响应截获」优化之外。
实测（4 次只读探针）
① 服务端 HTML 只有 47,294 字符，data-sku 出现 0 次、商品卡片 0 个 → 根本不是 SSR
② 商品数据在 api.m.jd.com/api?appid=search-pc-java 的明文 JSON： 商品数组 242,386 字符，含 wareId 30 个（正好等于页面上 30 张卡片）
③ 口径逐条吻合：技嘉 5070 卡片「¥ 7299 包邮」↔ jdPrice: 7299.00； 七彩虹「¥ 7399」↔ jdPrice: 7399.00 ⇒ 不会造成口径断裂
④ 同一 appid 还会被调用若干次（AB 配置，约 7KB）→ 用体积下限 20KB 干净区分
真实采集实测
京东 Ryzen 5 8400F 命中搜索接口：30 条（含店铺/到手价/wareId）
京东 RTX 5050 8G 命中搜索接口：30 条（含店铺/到手价/wareId）
京东 采集结束：2 个型号 → 60 条报价，耗时 27.8s
京东 分段计数：接口命中 2 · 有结果型号 2 ← 不是「回落DOM」
顺带拿到的东西：wareId 让我们可以自己拼 https://item.jd.com/{wareId}.html —— 京东第一次有了商品级去重键 （此前 Quote.url 是搜索页 URL，link_key() 返回空串，只能回落到 (平台,标题,价格)）。另有 shopName/stock/ finalPrice(到手价)/oriPrice/wareExtend(规格) 等 DOM 拿不到的字段。

已落地三处核验过的缺陷

  • 限流特征正文匹配漏 lower() —— URL 分支早就 (page.url or "").lower()， 正文分支一直是裸 in。后果：任何含大写 ASCII 的特征 （RGV587_ERROR、FAIL_SYS_USER_VALIDATE、Error_Code） 静默永不命中 —— 不报错、不熔断，只是安静地失效。 改为两边都 lower，但日志片段仍取原文（可读性）。
  • 京东 URL 特征补 risk_handler —— 同类项目里有，我们漏了。 它和 busy.html 同类，但 URL 里没有 busy 字样，旧特征抓不到。
  • 闲鱼 Quote.extra 补 item_id —— parse_search_payload 解析出来了，构造 Quote 时却被丢掉（只用来拼 URL）。 它是排查「同一商品为什么算了两次」的原始身份。
验证：自检 575 → 595；反向守卫 54/54 全部拦住（基线 595/595、还原 595/595， 0 未判定 0 未拦住），结论「全部守卫有效」；真实采集端到端通过；环境归零。

5错误分层（风控 / 登录 / 签名 / 未找到）三平台goofish-cli/core/mtop.py 他们分 5 类并明确「风控层刷 cookie 救不了」。我们只有单一 RateLimitError， healthcheck.py 注释自己承认「熔断器会把它误当成限流」
6拼多多完整错误码表PDDjynvch/pdd_spider 54001=风控 / 40001=登录失效 / 1101·40002=软风控 / 41001-41003=真无货。必须写成带键名形式（error_code=54001） —— 裸数字会被显卡型号撞上（我们刚修过 RTXA400016G 那次误熔断）
7「真无货 vs 被限流」用空态元素判定JD同类项目 把 _search 改三态，只有"什么都没有"才累加 empty_streak； 别再把无货型号当成被拦的燃料
8京东搜索前首页预热JD同类项目 我们拼多多有首页预热、京东没有（breaker.py 注释自己在怀疑这点）
数据质量与可观测性
9闲鱼单品快照表（按 item_id）闲鱼ai-goofish-monitor 算「首见/末见/观测次数/相对上次涨跌」——「这条挂牌从 3200 降到 2900」现在算不出来， 只有型号×平台×天的聚合序列
10闲鱼补字段：卖家昵称 / 原价 / 想要人数 / 标签闲鱼goofish-cli 接口里有、我们没取。同时修一个实证缺陷：Quote.seller 恒为占位符 「闲鱼卖家」（parse_search_payload 从不设该键）
11expect_response 绑定「点击 ↔ 目标响应」闲鱼ai-goofish-monitor 用 async with page.expect_response(...) 包住点击，消除跨型号的响应串味； 替换我们现在「被动监听 + 固定 page_wait_ms 猜等待」
12失败分类打标签 + 按标签回滚三平台speng4096/PyLoom 把 task_queue+breaker 从「平台级冷却」细化到「失败类型级」—— 网络抖动不再被当成风控白冷却几小时
13只重试网络异常，不重试业务异常PDDKumagt/price-monitor 别让所有异常退化成「空结果累加 empty_streak」
14失败路径也把刷新的 token/cookie 写回闲鱼goofish-cli 否则下一轮从更旧的状态起步
15京东卡片主选择器改 div[data-sku]JD同类项目 拿到稳定商品身份键（本轮已由 wareId 解决，此项降级为兜底）

04明确不采用（边界与已实测结论）

项理由
代理池 / 换 IP我们带登录态，换 IP = 风控眼里的「同一账号多 IP 高频访问」（账号盗用特征）
多账号 / 号池关键在被拦的是谁：请求频率已被排除（京东每轮只采 2 个型号仍被拦）； 同 IP 挂多账号 = 群控/养号特征，是从「限流」升级到「封号」的最快路径
官方开放平台 API已实测否决：京东联盟链路能通但覆盖率 0 （扫 30 频道 1211 条商品，显卡 0、CPU 0 —— 低佣金品类商家不参加推广）
JS 逆向 + 补环境产物带保质期；且我们「接住页面自己的响应」已经绕开了签名问题
滑块轨迹脚本化平台明确的安全控制，脚本化轨迹本身就是被检测特征 （23Star/xianyu-super-butler 做这个，我们不跟）
隐藏自动化指纹补丁我们自己 Popen 启动普通 Chrome 再 CDP 连接，本来就没有 Selenium 的注入特征； 加补丁等于主动断言「我在做自动化」
第三方打码平台把风控难题外包，账号风险不降反升
第三方付费数据聚合 APIKumagt/price-monitor 的真实数据源是付费 CPS 聚合 —— 与"自建追踪"的目标不符，且引入外部依赖

05方法学收获（比发现更值钱）

教训星数 ≠ 参考价值；README ≠ 代码

  • 本轮两条最有价值的证据来自 3★ 的仓库；而 9000+★ 的项目里有 仓库内零闲鱼代码的（ChattyPlay-Agent）。
  • DAILtech/PriceDive(82★) 的 fetch_price() 是 random.uniform 模拟数据 —— 只看 README 会当成正经项目。
  • 所以本轮强制要求：只写"看了代码确认"的事实，每条带 文件:行号； 无借鉴价值的如实写「无借鉴价值」，不为凑数把垃圾项目写成有价值。

教训「从未做过」不能只 grep 记忆文件 —— 必须查 git log

本轮我曾断言「官方开放平台 API 这条路线项目里从未评估过」， 并把它写进了长期记忆 —— 错的。它早已实测否决，结论存在三处， 而我只查了 MEMORY.md（那里恰好一行都没有，因为当时只写进了提交信息）。
结论：说「从未做过 / 没评估过」之前，必须查遍 MEMORY.md + 大日志 + git log 提交正文三处； 并且重要结论要从提交信息回写 MEMORY.md，否则下一个人会从"没写"推出"没做"。

教训先验证，再落盘

本轮补丁脚本把 write_text() 写在 ast.parse() 之前 —— 语法检查报错时，坏内容已经落盘并被提交进版本库 （reverse_check.py 少了收尾的 ]）。
规则：生成内容 → 先 ast.parse 验证 → 再写文件。
